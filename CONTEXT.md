# Thanes LIMS

Laboratory Information Management System — tracks samples through intake, testing, and storage.

## Language

### Storage Location

**Location**:
A node in the storage hierarchy where a sample can physically sit. Always one of four levels: Cabinet, Shelf, Slot, or Sub-slot, arranged as a strict 4-level tree (a node's children are always exactly one level below it — never skipped).
_Avoid_: Storage location (as a distinct term from Location), position, bin

**Cabinet**:
A root-level Location (no parent). The top of a storage tree, e.g. a fridge or cabinet unit.

**Shelf**, **Slot**, **Sub-slot**:
Locations one, two, and three levels below a Cabinet respectively. Each level's children are generated in a batch via a "generate children" action (a name prefix + count), not created one at a time.

**Leaf**:
A Location with no children. Only leaves can hold a sample. Leaf-ness is not a stored flag — it's inferred by fetching a Location's children and finding the list empty. Any level (including Cabinet) can be a leaf if it was never subdivided — e.g. a small fridge with no shelves is itself the storage spot.
_Avoid_: Sub-slot (as a synonym for leaf — most sub-slots are leaves, but a leaf can be any level)

**Full path**:
The human-readable chain from a Location's root Cabinet down to itself (e.g. "Fridge-A / Shelf-2 / Slot-4"). Computed live from the tree on every request — never stored. Renaming a node instantly changes the full path of everything beneath it.

**Active sample** (with respect to a Location):
A sample occupying a leaf whose status is `pending`, `testing`, or `completed` — i.e. still physically present. A sample with status `transferred` has left the building and no longer occupies its leaf, even though the sample record still references it.
_Avoid_: Occupied, assigned (these don't distinguish active vs. transferred)

**Put-away**:
The act of assigning a sample to a leaf Location, distinct in time and intent from sample intake. A sample is always created first (unassigned), then put away separately. Put-away can also mean *moving* a sample already at one leaf to another.
_Avoid_: Assign, store (use "put-away" for the workflow; "assigned to" is fine for the resulting state of a sample)

## Sample Identity

**Barcode ID**:
An optional second identifier on a Sample, separate from its Sample ID. Either typed in by the operator (a code already printed on the tube) or generated by the system after the Sample exists. Unique when set. What a physical scan resolves to.
_Avoid_: Sample ID, code (the Sample ID `SMP-2569-00001` is the identifier the rest of the system quotes; Barcode ID exists for the physical world)

**Sticker**:
The printable label carrying a Sample's barcode, rendered as a PDF by the backend rather than laid out in the browser. Comes in several physical sizes and in either 1D or 2D symbology, because different label printers and different tube sizes are in use. A Sample with no Barcode ID still has a Sticker — it encodes the Sample ID instead, so nothing is ever unscannable.

**Custodian**:
The User responsible for a Sample, a piece of Equipment, or an Inventory Item. Always a User, chosen from a list — never a typed-in name.
_Avoid_: Owner, responsible person

## Storage Location (two trees)

**Location Kind**:
Which of the two storage trees a Location belongs to. `sample_storage` is the original tree (Cabinet → Shelf → Slot → Sub-slot) where a Sample can only sit on a Leaf and only one Sample at a time. `equipment_storage` is a second, deeper tree (Building → Room → Zone → Cabinet → Shelf) shared by Equipment and Inventory Items, with no occupancy rule — a room legitimately holds many machines and many boxes at once. The level names Cabinet and Shelf appear in both trees at different depths and only mean something once you know the Kind.
_Avoid_: Location type (Level Type already names the rung; Kind names the tree)

**Location Barcode**:
A scannable code carried by every Location node in both trees. Scanning it resolves straight to that node, sparing the operator from walking the tree by hand. Scanning a node that is not a Leaf is not an error in the workflow — it narrows the choice to that node's subtree, and the operator picks the Leaf from there.

## Equipment

**Manufacturer**:
Who made a piece of Equipment or an Inventory Item — a plain descriptive name with no contact details behind it.
_Avoid_: Vendor (a Vendor is a master record you can call; a Manufacturer is a word on a nameplate)

**Vendor**:
The supplier you buy from or call for service — a master record with contact details, referenced from Equipment, Inventory Items and Purchase Orders. Never re-typed per form. Can be created without leaving the form that needed it, but what gets created is the same master record, not a local copy.
_Avoid_: Supplier, Manufacturer

**Calibration Schedule**:
One standing calibration commitment on a piece of Equipment — a name (e.g. "สอบเทียบภายนอก"), the date it is next due, and optionally how often it repeats. One machine carries several at once, tracked independently: an internal check every month and an external certification every year are two Schedules, not one.
_Avoid_: Due date (ambiguous — a machine has as many due dates as it has Schedules)

**Calibration Event**:
A record that a calibration was actually performed: what type, what was measured, what the acceptance band was, whether it passed, and who did it. Append-only — a wrong entry is corrected by a new Event, never by editing history. Logging one against a Schedule that repeats moves that Schedule's due date forward on its own.

**Calibration Certificate**:
The document evidencing one Calibration Event, attached to that Event after it is logged. Belongs to exactly one Event.

## Inventory

**Inventory Lot**:
One batch of stock of an Inventory Item, with its own lot number, its own expiry, and its own quantity. An Item's on-hand quantity is the sum of its Lots and nothing else — stock enters only by receiving a Lot and leaves only by issuing from a Lot.
_Avoid_: Stock, quantity (as something you can set directly — there is no such act)

**Receiving**:
Booking incoming stock into a Lot. Receiving under a lot number that already exists tops that Lot up rather than creating a second one — the same delivery arriving in two boxes is one Lot.

**Stock Issue**:
A withdrawal drawn from Lots the operator names explicitly. The system never picks the Lot. Asking for more than a Lot holds is a question, not an error: the operator either draws the remainder from another Lot, or insists — and the Lot is allowed to go negative, which is how a disagreement between the shelf and the system becomes visible instead of silently absorbed.
_Avoid_: Auto-allocation, FEFO pick
